 ⏺ One real problem surfaced, and it changes the grammar — so I'm raising it
   rather than writing a design you can't lex.

   3⃣ and 6⃣ start with the ASCII bytes 33 and 36 — the digits 3 and 6. They are
   U+0033 U+20E3, a digit followed by a combining enclosing keycap. So when your
   lexer is in START and sees byte 0x33, it cannot tell whether a number 3 or the
   type keyword 3⃣ is beginning. The current NUMBER state would read 3, then hit
   0xE2 — a non-digit, non-alpha byte — and emit number("3"), leaving ⃣ to blow
   up as an unexpected byte.

   This is fixable in the hand-written state machine without regex: NUMBER must,
   on seeing 0xE2, look ahead for the exact two bytes 83 A3 and, if the digit run
   was a single 3 or 6, emit the type token instead. That's about 8 extra lines
   and one extra state — but it is genuine lookahead inside a state machine, and
   it makes 33⃣ and 3⃣5 ambiguous cases you must define.

   Your call:

   Two things to watch when you implement:

   The keycap collision is the one piece of real lexer work. 3⃣ is the ASCII byte
   3 followed by E2 83 A3, so NUMBER has to peek two bytes past an 0xE2 and
   decide between kw_i32, kw_i64, and a genuine error. design.md has the full

   Character columns need one change in the main loop: increment col only when
   the byte is a UTF-8 lead (b < 0x80 or b >= 0xC0). Easy to forget, and it

      │                                                                         │
      │ - Both 1-based; the first character of a line is column 1.              │
      │ - col counts characters: in lex's main loop, col += 1 only when the     │
      │   byte is a UTF-8 lead (b < 0x80 or b >= 0xC0). Continuation bytes      │

      │ - Later passes report from the position already stored on the node.     │
      │ - End-of-line errors: last.col + len(last.text), characters — correct   │
      │   for free                                                              │
      │   once .text is a str (§1.2).                                           │
      │ - byte_text() keeps printing a raw stray byte as \xNN.                  │
